# Independent business-writing review

Reviewed `src/suiroai/demo/business_response.py`, `backend.py`, and focused writer/backend tests against the user's requirement for an actual second native prompt producing a useful explanation for a nontechnical business owner. This reviewer authored the separate freeze utility, not the writer implementation. No real model call or December outcome access was performed for this review.

Found and fixed one consent defect: a reentrant progress callback could revoke the approved task immediately before writer dispatch, but the writer did not recheck consent after that callback. It now checks again before preparing the trace and calling the host. A regression test revokes consent from progress and verifies that no native host call or outbound prompt trace occurs. Backend publication also retains its final exact-approval consent check.

The production backend invokes the writer by default after completed findings, rather than only exposing an unused helper. The writer makes a separate native execution with no overall deadline. It releases only original findings, aggregate CSV facts, allowlisted comparison/plan/workload context and a hashed source manifest. Raw transaction rows, the delivered CSV rows, fitted model and HTML are not released to the writer. The new native stage has separate read-only release, output, evidence and prompt-trace directories. Source snapshots and returned narrative/result bytes receive immutable artifact references. Existing CSV/HTML/model files are not rewritten; adopted narrative has separate lineage and leaves verification flags false.

Prompt grounding requires supplied measured facts, baseline identity and evaluation period; it prohibits invented incumbent rules, savings, timings/prices, deployments/integrations or guaranteed improvements from better data/retraining. Automation explanation is conditional on evidenced calculations rather than a claim that scheduling/upload integrations exist. Synthetic-input cautions and decision-relevant limitations remain, without generic trust-status notices. Writing failures retain the useful original explanation and internal error evidence; they do not replace the CSV or add customer-facing writer warnings.

Validation: `PYTHONPATH=src .venv/bin/python -m pytest tests/demo/test_business_response.py tests/demo/test_backend.py -q` — **17 passed**. All host calls in these tests are explicit doubles or mocked writer boundaries; no paid execution was used. Tests cover default backend wiring, exact source/result hashes, bounded source allowlist, unchanged existing files, writer failure fallback, source tampering, before/after consent and the new progress-revocation case. Module purpose documentation now also links DSC-60.

Limits: transport hashes and instructions do not prove factual accuracy, reading quality or complete semantic fidelity of generated prose. Additional context files are snapshotted and hashed when the writer starts; that proves these writing inputs, not their original analytical provenance or untouched outcome history. A genuine second-turn result still needs inspection against its source facts, and this review grants no analytical, performance or broader milestone acceptance.
