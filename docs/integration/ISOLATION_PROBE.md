## macOS scratch-root finding

The real control-phase report at `/private/tmp/dsc26-native-isolation-7umtqgsm/evidence/isolation-evidence.json` records successful unreleased sentinel and symlink reads and an outside-output file creation, all under `/private/tmp`. The protected released-input write and network attempt were denied. The probe stopped before a model turn. Its correctly echoed named profile alone did not establish effective read isolation.

The exact source provides a specific explanation for this pattern without assuming a legacy-profile conversion defect. `:minimal` enables platform defaults for a restricted policy. For the macOS **Process** profile, Seatbelt adds scratch read/write roots at `/private/tmp` and `/private/var/tmp`, preserving explicit restrictions and read-only carveouts. Filesystem-helper profiles do not inherit these scratch grants. The source regression `process_platform_defaults_allow_scratch_without_granting_it_to_filesystem_helpers` expressly tests that distinction. The filesystem-root deny is intentionally omitted from the lowerer's explicit unreadable-root list so it does not erase narrower allowed roots; that broad deny therefore does not exclude the scratch defaults. [Platform-default selection and precedence](https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/protocol/src/permissions.rs), [Seatbelt process lowering](https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/sandboxing/src/seatbelt.rs), [scratch grants and carveouts](https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/sandboxing/src/seatbelt_scratch.rs), [native source regression](https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/sandboxing/src/seatbelt_tests.rs)

A stronger candidate explicitly denies the physical scratch roots `/private/tmp` and `/private/var/tmp`, and the canonical original `TMPDIR`, while retaining the more-specific released-input read and output-directory write entries. Source resolution gives deeper paths precedence and denies precedence over equal-depth writes. Non-root literal denies remain explicit unreadable roots; the scratch builder carries those restrictions into its read/write exclusions. Narrower released/output roots are separately allowed and are not erased by a broader parent exclusion. This source finding alone did not establish a runtime pass. Keep the unreleased fixtures in the same temporary tree; moving them elsewhere would hide the observed leak. Check the physical and trusted alias paths and stage symlink under the strengthened policy before any Data turn.
