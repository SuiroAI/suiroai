# DSC-26 native isolation probe boundary

2026-10-17 · source review and proposed synthetic checks · **customer dispatch remains blocked**.

This review made no model calls, read no customer records, and changed no host configuration. A successful synthetic Data calculation does not establish released-input isolation. The next probe must exercise the exact native permissions and reachable tool surface intended for a customer stage.

## What the native sources establish

At the installed CLI's exact source tag, `rust-v0.163.0`, the model's `view_image` handler obtains the selected turn environment's sandbox context and passes it to both metadata lookup and file reading. Its regression test `handle_passes_sandbox_context_for_local_filesystem_reads` expects a failure when a required sandbox runtime is unavailable. This is useful source evidence, not a successful test of this installed host. [Image handler and test](https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/core/src/tools/handlers/view_image.rs)

`FileSystemSandboxContext::should_read_from_sandbox` requires sandboxed reads when the profile lacks full-disk read access. `LocalFileSystem` applies that decision to reads, metadata, directory listing and walking; `SandboxedFileSystem` runs those operations through its sandbox helper. This supports a native candidate for protecting file tools as well as commands. Actual callers must supply their turn context. [Sandbox context](https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/file-system/src/lib.rs), [local filesystem routing](https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/exec-server/src/local_file_system.rs), [sandboxed filesystem](https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/exec-server/src/sandboxed_file_system.rs)

The core handler module and tool registration plan at this tag do not register tools named `read_file`, `list_dir` or `grep_files`. They register shell execution, `view_image`, MCP/resource tools and extension contributions, among others. Do not demand an unavailable tool or assume an extension/MCP tool with a similar name shares the filesystem implementation above. [Core handlers](https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/core/src/tools/handlers/mod.rs), [tool registration](https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/core/src/tools/spec_plan.rs)

Trusted app-server control RPCs are a separate boundary. A frontend's `fs/readFile` request takes a host path, rather than a model tool invocation. The trusted adapter may resolve approved source bytes for staging. An unrestricted frontend RPC alone is not evidence that the analytical worker can bypass its profile; neither should a probe implement a bridge exposing that RPC to the model.

Named permission-profile selection is experimental in the native thread protocol. The candidate uses per-process configuration only: root reads denied, minimal runtime and exact Data resource reads allowed, released input reads allowed, stage outputs writable, command networking disabled, and approvals denied. Effective settings must be checked because legacy sandbox configuration can override profiles. Filesystem/network profiles cover local commands; connectors, MCP, browser and other surfaces have separate controls. [Permissions documentation](https://learn.chatgpt.com/docs/permissions), [thread protocol](https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/app-server-protocol/src/protocol/v2/thread.rs)

## Evidence the synthetic probe must retain

1. Preserve the exact launch overrides, selected profile, effective thread/environment settings, CLI/Data identity and explicit Data attachment. Reject a fallback to broad read access, unresolved profile selection or permission escalation. Use a fresh synthetic stage, with no raw customer source path in its allowed reads.
2. Before the Data turn, exercise bounded native commands under that same profile: released-file read and output write succeed; unreleased sibling sentinel, direct absolute read, and stage symlink to that sentinel fail. Include a negative write outside the output namespace and a bounded network denial. A controller's unsandboxed `cat` is not this test.
3. In the Data turn, exercise the actual exposed model file tools. For `view_image`, use valid tiny synthetic PNGs: a released PNG must load; an unreleased PNG outside the stage and a stage symlink to it must produce genuine native access errors. An invalid-image decoding error proves bytes were readable, not denied. A model declining the call or saying access was denied is insufficient evidence.
4. Retrieve paginated `thread/items/list` results, retaining only relevant tool calls/outputs, native command evidence and stage artifacts. The installed generated schema includes `functionCallOutput` with `id`, `name` and `output`. Correlate the attempted `view_image` path/call with its actual error output. `imageView` contains only identity/path and is emitted after a successful read, so its absence cannot prove denial. No internal raw-response notifications, hidden reasoning or complete skill contents are required. [Native item protocol](https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/app-server-protocol/src/protocol/v2/thread.rs), [failure-to-tool-output conversion](https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/core/src/tools/parallel.rs)
5. Preserve the thread's actual MCP/app/plugin capability inventory and effective disabling controls. Thread-scoped `mcpServerStatus/list` supports tools, resources, templates and discovery errors; paginate it. A failed catalog lookup is not an empty catalog. `disabledPluginIds`, command network denial or a prompt to avoid connectors does not establish that their tools are unreachable. `features.apps=false` and disabling configured/plugin MCP servers are candidate controls whose compatibility with Data must be demonstrated in this same run. Keep Data's required skill active; do not invent a replacement runtime. [MCP/plugin configuration assembly](https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/core/src/config/mod.rs), [MCP resource dispatch](https://github.com/openai/codex/blob/rust-v0.163.0/codex-rs/core/src/tools/handlers/mcp_resource/read_mcp_resource.rs)

These checks can support a bounded isolation claim for the tested CLI version, host, profile and actual tool inventory. They cannot prove arbitrary future tools safe. Any exposed file/connector/browser capability that lacks an enforced restriction or genuine denial remains an integration blocker. A shell-only pass leaves that blocker intact. Customer execution stays disabled until the reviewed mechanism is implemented in the adapter and the current DSC-25 approval and DSC-10 permission are present.
